# Verification

Verified on November 1, 2026 using an isolated Chromium browser against the local static server.

## Passed

- 14 deterministic timer assertions: exact transitions, fractional pause/resume, long callback delays, completion, restart, skipping, zero rests, no trailing rest, and empty workouts.
- Browser interactions: start/pause/resume/reset, rest countdown, completion and replay.
- Workout and exercise creation, editing, confirmed deletion, cancellation, and persistence after reload.
- Exercise reordering by mouse in both directions, keyboard Up/Down and Home/End, and Chromium touch events. Exercise durations and rest periods stay attached; order persists after reload and the timer follows the updated lineup.
- Drag cancellation with Escape, dropping outside the list, and dropping without changing position preserve the order. Changed positions reset the session; simple handle clicks do not pause a running timer.
- Long workout lists scroll at the viewport edge during dragging. Handles fit at 320px and 390px; the dark-mode mobile screenshot was visually inspected.
- JSON export/import round-trip, import cancellation, invalid JSON and invalid duration rejection, safe rendering of HTML-like names.
- Multi-file import of the three converted Tabata JSON files, preserving existing workouts and persisting the merged collection after reload.
- Repeated imports and matching IDs across files create independent copies with unique IDs; existing workouts stay unchanged.
- Invalid files reject the entire batch. Empty imports and imports exceeding the 200-workout collection limit leave saved data unchanged.
- An empty saved collection remains empty after reload.
- Theme preference persists across reloads.
- No horizontal overflow at viewport widths of 320, 390, and 768 pixels.
- Missing starter file and blocked storage leave the app usable and explain how to keep changes.
- No JavaScript page errors in the main integration run.
- JSON syntax and Git whitespace checks.

Desktop, mobile-width, and dark-mode screenshots were visually inspected. These checks use Chromium viewport sizes, not physical iOS or Android devices. Background audio and screen wake behavior depend on browser and operating-system permissions; see README.md.

The browser suite supplies its own starter collection so tests do not depend on an optional root `workouts.json`. Multi-file checks also load the real JSON files in `workouts/`. The native phone file picker's multi-select behavior has not been tested on a physical device; sequential single-file imports also preserve existing workouts.
